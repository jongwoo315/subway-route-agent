# #193 설계 — 채점이 빠진 중간 역을 채워서 본다

## 무엇을 바꾸나

#188 게이트에서 LLM + 도구 정답률이 6번 실행 중 최대 1/10이었다. 다시 채점해 보니 틀린 답 상당수가 길은 맞게 골랐는데 지나는 역을 다 쓰지 않은 것이었다(#188 main 실행 q2: `서울역(4) → 동대문역사문화공원(4) → 동대문역사문화공원(2) → 잠실(2)` — 정답과 같은 길, 중간 역 13개 생략).
지금 채점(`grade.py`)은 이웃하지 않은 두 역이 붙어 있으면 `경로 끊김`으로 틀리게 본다.

jw 기준은 둘 중 하나를 고르라고 했다: 지나는 역을 확실히 채점하거나, 이동 경로를 정확히 계산했으면 역이 다 안 나와도 정답으로 본다. 이 티켓은 **뒤쪽**을 고른다.

- 바꾸는 stub: 채점 규칙의 「이웃한 역끼리만 이어진다」
- 그대로 두는 것: 지시문(`SYSTEM`·`TOOLS_SYSTEM`), 도구 셋, 질문 셋, 정답(다익스트라)

## 설계 결정

| 결정 | 고른 것 | 이유 |
| --- | --- | --- |
| jw 기준의 두 갈래 중 | 빠진 역을 채워 채점한다 | #188 데이터에서 LLM이 지시문을 어기는 쪽이 일정하다(5번 실행 모두). 지시문을 고쳐 역을 다 쓰게 만드는 것은 LLM 쪽 수정이라 결과가 실행마다 흔들리고, 채점은 코드라 같은 답에 같은 점수를 낸다. jw가 #188에서 재려던 것은 「최단거리를 정확하게 계산하나」라서 길과 소요 시간이 맞으면 그것이 측정 대상이다 |
| 채우는 규칙 1 — 같은 호선 | 붙은 두 역이 같은 호선이고 그래프에서 이웃하지 않으면, 그 호선 간선만으로 두 역 사이 가장 짧은 길의 역을 넣는다(`tools.travel_seconds`와 같은 규칙) | 「같은 호선 안에서는 갈아타지 않고 간다」만 가정한다. 다른 호선을 끼워 넣지 않는다 |
| 채우는 규칙 2 — 갈아타는 역을 한 번만 쓴 것 | `A(1) → B(2)`이고 B가 1호선에도 있으면 `A(1) → … → B(1) → B(2)`로 채운다 | 지시문은 갈아타는 역을 두 번 쓰라고 했지만, 한 번만 써도 길은 정해진다 |
| 채울 수 없는 것 | 위 두 규칙으로 못 잇는 곳이 하나라도 있으면 지금처럼 `경로 끊김` | 예: `서울역(1) → 잠실(2)` — 잠실은 1호선에 없고 서울역은 2호선에 없다. 어디서 갈아탔는지 답이 말하지 않았다 |
| 순환선 방향 | 2호선처럼 양쪽으로 갈 수 있으면 짧은 쪽으로 채운다 | 답이 방향을 말하지 않았다. 짧은 쪽으로 채우면 긴 쪽을 생각한 답도 맞게 볼 수 있다. 그래서 채운 역 수를 리포트에 같이 적어 보이게 한다 |
| 맞음 판정 | 채운 경로로 지금과 같은 조건(출발·도착역, 환승 상한, 시한, 실제 소요 시간 = 정답)을 본다 | 채우는 것 말고는 규칙을 바꾸지 않는다 | <!-- style-exempt -->
| 리포트 | 리포트·비교 리포트에 `채운 역` 열을 더한다(질문마다 채운 역 수). 비교 리포트 머리에 답하는 쪽마다 「채우지 않고도 맞은 질문 수」를 같이 적는다 | 지금까지의 엄격한 정답률(#186~#188)과 이어서 읽을 수 있다 |
| 지시문을 안 지킨 원인 | `--raw`에 질문마다 도구 호출 기록(도구 이름·인자·결과 앞 200자)을 남긴다(#188 리뷰 #7). 측정 때 역을 빠뜨린 답에서 그 호선의 `line_stations`를 불렀는지 센다 | #188 유보 이유 「지시문이 지켜지지 않은 이유」. 지금은 도구 결과가 어디에도 안 남아 셀 수 없다 |
| 검증 데이터 | #188 main 실행 원문(`tests/fixtures/gate188/`)을 새 채점으로 다시 채점하는 테스트 | 실제 LLM 답이라 손으로 만든 예보다 경우가 다양하다. 이 원문은 API 없이 쓸 수 있다 |

## 참고 값 — #188 게이트에서 main이 손으로 다시 채점한 것

| --- | --- | --- | --- |
| LLM + 도구 | 0/10 | 5/10 | q1, q2, q3, q9, q10 |
| LLM 혼자 | 0/10 | 0/10 | 없음 |

- 이 스크립트도 main이 쓴 것이라 새 채점 코드와 같은 생각에서 나왔다. 둘이 같이 틀릴 수 있다. 그래서 손으로 만든 사례(plan Task 1)를 따로 둔다
- 새 채점은 규칙 2가 더해져 이 표보다 맞은 질문이 늘 수 있다. 늘었으면 어느 질문이 규칙 2 때문인지 적는다
