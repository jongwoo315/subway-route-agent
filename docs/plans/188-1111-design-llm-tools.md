- 바꾸는 stub: 답하는 쪽 목록의 「LLM + 도구」 빈 자리와 리포트의 `도구 호출` 열(지금 늘 0)
- 그대로 두는 stub: 환승 180초, 기다리는 시간 0, 채점 규칙(`grade.py`) <!-- style-exempt -->

## 설계 결정

| 결정 | 고른 것 | 이유 |
| --- | --- | --- |
| 도구가 주는 것 | 정보만 준다. 여러 호선을 거치는 최단 경로나 그 소요 시간은 주지 않는다 | 티켓 실패 징후: 도구가 최단 경로를 계산해 주면 정답을 건네는 셈이라 비교가 안 된다. 경로를 고르는 일은 LLM에게 남긴다 |
| 도구 셋 | `find_station(name)`: 그래프의 역 이름과 그 역을 지나는 호선 목록. 없으면 이름에 `name`이 들어간 역 후보 최대 10개<br>`line_stations(line)`: 그 호선의 구간 목록 `[{from, to, seconds, one_way}]`. CSV 행 순서 그대로이고, 지선은 갈라지는 역에서, 순환선은 처음 역으로 돌아와 이어진다<br>`travel_seconds(line, from_station, to_station)`: 한 호선 안에서만, 갈아타지 않고 두 역 사이를 갈 때의 소요 시간(초). 경로는 돌려주지 않는다 | 티켓의 세 도구(역 검색, 노선 조회, 두 역 사이 소요 시간)를 그대로 옮겼다. `travel_seconds`를 한 호선으로 묶은 것이 위 행의 결정이다 |
| 환승 시간 | LLM + 도구의 지시문에 「환승 한 번은 180초」를 적는다. LLM 혼자 지시문(`SYSTEM`)은 고치지 않는다 | 정답 소요 시간에 환승 180초가 들어가므로 이 값 없이는 LLM이 최단 경로를 고를 수 없다. LLM 혼자 지시문을 고치면 #186·#187과 값을 비교할 수 없게 된다. 두 지시문의 차이는 리포트 머리에 적는다 |
| 답 형식 | LLM 혼자와 같은 JSON(`path`, `seconds`)과 같은 `_parse`를 쓴다 | 파싱 규칙이 같아야 정답률 차이가 도구 때문인지 읽을 수 있다 |
| 도구 호출 반복 | Responses API에 도구를 함께 주고, 응답에 `function_call`이 있으면 도구를 실행해 결과(`function_call_output`)를 붙여 다시 부른다. `function_call`이 없는 응답의 `output_text`가 최종 답이다 | OpenAI 함수 호출의 기본 방식이다. 이미 쓰는 `openai` 패키지로 된다 |
| 도구 호출 상한 | 질문 하나에 25번. 넘으면 그 질문은 `parse_error="도구 호출 상한(25)에 닿았다"`로 끝낸다 | 상한이 없으면 한 질문이 비용을 다 쓸 수 있다. 최종 답을 받지 못한 것이라 파싱 실패로 센다. 실제로 몇 번 닿았는지 리포트에서 따로 셀 수 있게 이유 문자열을 고정한다 | <!-- style-exempt -->
| `Answer.tool_calls`·`tokens` | 도구 호출 수, 그리고 반복하며 부른 모든 요청의 입력 + 출력 토큰 합 | 리포트 `도구 호출`·`토큰` 열을 실제 값으로 채운다 |
| 명령 하나로 비교 | `--answerer`가 여러 값을 받는다(`--answerer llm llm-tools`). 답하는 쪽마다 기존 리포트(`reports/<이름>.md`)를 쓰고, 둘 이상이면 비교 리포트 `reports/compare.md`를 더 쓴다 | jw 기준 뒷부분 「같은 질의를 했을 때 결과를 비교할 수 있다」와 티켓 통과 기준(명령 하나로 나란히)을 그대로 옮겼다 |
| 비교 리포트 | 머리: 답하는 쪽마다 정답률·파싱 실패·도구 호출 합·토큰 합·응답 시간 합. 표: 질문마다 정답 시간, 그리고 답하는 쪽마다 `맞음`(O/X)·`답 경로 소요 시간`(그래프로 잰 실제 소요 시간, 경로가 끊기면 `끊김`)·`답이 말한 시간` | 같은 질문의 결과를 한 줄에서 읽는다 |
| `--raw` | 답하는 쪽이 둘 이상이면 `<파일명>-<답하는 쪽>.json`으로 나눠 쓴다 | 하나면 지금처럼 그 파일에 쓴다 |
| 테스트 | API를 부르지 않는다. 실제 키로 한 번 녹화한 도구 호출 응답(질문 2개)을 가짜 client가 차례로 돌려준다 | 티켓: 녹화해 둔 도구 호출 응답으로 돌린다. 이 레포에는 CI가 없어 `pytest`가 그 자리다 | <!-- style-exempt -->

## 「최단거리」를 무엇으로 재나

- jw 기준은 「역간 최단거리」를 쓴다. 이 프로젝트의 정답은 #185부터 **소요 시간**이 가장 짧은 경로다(`docs/concepts.md` 용어 `정답`). CSV에 km 열도 있지만 그래프와 채점은 소요 시간만 쓴다
- 그래서 「더 정확하게 계산한다」는 정답률(답 경로의 실제 소요 시간이 정답 소요 시간과 같고 조건 어김이 없는 질문 수)로 잰다
- 「계산」 쪽은 값을 하나 더 적는다: 답이 말한 시간(`seconds`)이 정답 소요 시간과 같은 질문 수. LLM 혼자는 지금까지 모든 답이 `seconds` null이었다. 임계값은 두지 않는다

## 정답률 최대값

- q6·q7은 정답 없음 질문이라 어떤 답도 맞을 수 없다(#187 리뷰 #4, 미룸). 그래서 두 답하는 쪽 모두 정답률 최대가 8/10이다
