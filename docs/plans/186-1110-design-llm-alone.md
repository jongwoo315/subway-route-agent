# #186 설계 — 답하는 쪽 stub을 「LLM 혼자」로 바꾼다

## 무엇을 바꾸나

#185 skeleton은 질문 3개 → 답하는 쪽 → 다익스트라 정답과 채점 → 리포트까지 끝까지 돈다. 답하는 쪽은 빈 답을 주는 stub 하나뿐이다. <!-- style-exempt -->
이 티켓은 그 자리에 「LLM 혼자」를 넣는다. LLM은 질문 문장만 받고, 역 목록·그래프·도구 없이 경로와 소요 시간을 답한다.

- 바꾸는 stub: `src/subway_route_agent/answerers.py`의 `ANSWERERS` — `llm`을 추가한다. `stub`은 그대로 둔다
- 나머지 stub(환승 180초, 기다리는 시간 0, 질문 3개, LLM + 도구 빈 자리)은 그대로다 <!-- style-exempt -->

## 설계 결정

| 결정 | 고른 것 | 이유 |
| --- | --- | --- |
| LLM 제공자 | OpenAI Responses API (`openai` 패키지) | `OPENAI_API_KEY`가 `~/.zshenv`에 있다. Anthropic 키는 이 맥에 없다. 다른 레포(cheongyak-extract)가 같은 API를 쓴다 |
| 모델 | 환경변수 `OPENAI_MODEL`, 없으면 `gpt-5.4-mini` | cheongyak-extract가 이 모델로 jw 계정에서 돌고 있다. 모델 비교는 이번 범위가 아니다 |
| LLM이 받는 것 | 질문 문장 + 답 형식 설명(시스템 지시) | 「LLM 혼자」의 정의다. 역 목록·호선 데이터·정답을 넣지 않는다. 넣으면 다음 티켓(LLM + 도구)과 비교할 기준이 사라진다 |
| 답 형식 | structured output JSON schema: `path`=[{`station`, `line`}] (지나는 역 전부, 호선 1~8 정수), `seconds`=정수 또는 null | 채점(`grade.py`)이 이웃한 두 노드 사이 간선으로 경로를 검사하므로 지나는 역을 빠짐없이 받아야 한다 |
| 읽지 못한 답 | 그 행만 `Answer.parse_error`에 이유를 적고 빈 경로로 둔다. 실행은 계속한다 | #185 리뷰 #9(모양이 틀린 답이 오면 `grade()`가 예외로 죽는다). 행 하나 때문에 리포트 전체를 잃지 않는다 | <!-- style-exempt -->
| API 오류 | 잡지 않는다. 메시지를 내고 exit code 1로 끝난다. 키가 없으면 실행 전에 exit 2 | 401·quota는 다시 해도 안 된다. 일시 오류는 SDK 기본 재시도(2회)에 맡긴다 |
| 토큰 | `Answer.tokens` = 입력 + 출력 토큰. 리포트 열 `토큰` 추가 | 이 프로젝트가 재는 것이 「무엇이 비싸지나」다. LLM 혼자가 첫 기준값이 된다 |
| LLM 원문 | `Answer.raw`에 보관. `--raw PATH`면 질문별 원문을 JSON으로 쓴다 | 「다시 잰다」 구간에서 왜 못 읽었는지 볼 자리. 녹화해 둔 응답(테스트 fixture)도 여기서 만든다 |
| 테스트 | API를 부르지 않는다. 가짜 client가 녹화해 둔 응답을 돌려준다 | `ticket-breakdown` §테스트 두 종류 — LLM 단계는 녹화 응답으로 CI, 실제 호출은 따로 |
| 기본 답하는 쪽 | `stub` 그대로. LLM은 `--answerer llm` | 키 없이도 `uv run subway-eval`이 끝까지 돌고, 테스트가 실수로 API를 부르지 않는다. jw가 기본값을 `llm`으로 원하면 Kickoff에서 adjust |
| 리포트 파일 | 답하는 쪽마다 `reports/<답하는 쪽>.md`. `reports/skeleton.md`는 `reports/stub.md`로 옮기고 손으로 적은 「jw 기준 측정」 절을 뺀다 | #185 리뷰 #5(다시 돌리면 손으로 적은 절이 사라진다). 생성 파일에는 손으로 쓰지 않는다. 측정 기록은 PR 본문과 `docs/decisions.md`에 남는다(#185 측정은 PR #1 본문에 그대로 있다) |

## 정답률은 이 티켓의 목표가 아니다

- LLM 혼자는 지나는 역을 전부 맞혀야 하고, 환승 180초 stub까지 맞혀야 소요 시간이 정답과 같아진다. 정답률 0/3도 나올 수 있다
- 정답률·지어낸 역·조건 어김은 다음 티켓(LLM + 도구)과 비교할 기준값으로 적기만 한다
- 점수를 올리려고 프롬프트에 역 목록·정답·질문별 힌트를 넣지 않는다

## 이번에 안 하는 것

- 질문 늘리기, q2·q3 손 계산 (#187)
- 모델 여러 개 비교, 프롬프트 여러 개 비교
- 같은 질문을 여러 번 돌려 실행마다 결과가 얼마나 달라지는지 보는 것. 이번에는 두 번 돌린 값만 나란히 적는다
